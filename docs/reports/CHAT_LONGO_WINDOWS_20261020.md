# Conversa longa no cliente Windows — 20/10/2026

O ensaio executou o `LocalAuthor.Client.exe` instalado, em uma instância isolada do WebView2, com gateway HTTPS, certificado vinculado, perfil e banco descartáveis. O aplicativo e o banco habituais do usuário não receberam as mensagens de teste. O histórico contém 180 mensagens, sendo 90 respostas sintéticas com C#, TypeScript e SQL, totalizando 204.796 caracteres. Esses dados exercitam a apresentação; não demonstram geração real nem qualidade do modelo.

A janela nativa foi conferida na sua dimensão original, com escala Windows de 125%. Outros tamanhos foram emulados no próprio WebView2: 320, 390, 1024, 1440 e 1920 pixels. O ensaio verificou os temas claro/escuro, início/meio/fim do histórico, preservação literal de Unicode e comentários, código com linhas extensas, ausência de execução de markup, caixa de mensagem visível, rascunho multilinha, lateral recolhida, investigação aberta e restauração após recarregar. As margens continuam alinhadas e não houve transbordamento horizontal da página ou do histórico. Código extenso quebra visualmente conforme a largura, sem alterar o texto armazenado.

Foram encontrados e corrigidos dois problemas:

- O editor JavaScript não reconhecia declarações como `const título = "Ação";`, embora o classificador Python as reconhecesse. A apresentação passou a aceitar letras e números Unicode nessas declarações. Os casos compartilhados entre navegador e servidor cobrem os identificadores acentuados e preservam a classificação conservadora dos demais exemplos; isso não implementa um parser completo de linguagens.
- O gateway recusava imediatamente o quinto pedido simultâneo, inclusive arquivos necessários para abrir a interface. As leituras de rotas estáticas explicitamente permitidas agora aguardam até cinco segundos em uma fila limitada a 16 esperas. O limite de quatro requisições em execução, a autenticação e a recusa imediata de sobrecarga nas APIs permanecem. A correção requer atualizar o gateway do servidor; os clientes continuam carregando a interface central sem reinstalação.

A repetição do ensaio nativo passou em 56 controles, sem erros JavaScript nem falhas HTTP ao carregar os scripts. O ensaio geral da interface passou em 97 controles. A compilação .NET passou sem avisos ou erros. `scripts/lan-static-smoke.py` acrescenta 13 controles com HTTPS real: rajadas de arquivos, bytes idênticos, concorrência máxima, fila cheia, prazo de espera, recuperação após sobrecarga e proteção das APIs. O CI executa esse ensaio no Windows e no Linux.

A suíte Python local executou 722 testes: 719 aprovados, zero falhas/erros e três testes de links simbólicos não executados por falta de privilégio Windows. Os registros e capturas, inclusive tentativas anteriores e falhas intermediárias corrigidas, ficam em evidências privadas. A abertura do histórico mediu aproximadamente meio segundo nessa execução isolada; isso não mede latência de geração, outros equipamentos nem um segundo computador físico.
